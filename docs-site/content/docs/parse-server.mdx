## 功能

文件解析服务是独立的 HTTP 服务，只做文件解析，不启动桌面端与索引监听。上传文件后返回 Markdown，支持 PDF、Office 文档、纯文本、Markdown、电子书与音视频。

解析按以下顺序自动尝试，某一步失败后降级到下一步，错误原文会保留在任务记录里：

1. PDF 与图片：MinerU 云端解析（需配置 Key，未配置或失败时跳过）。
2. Office 与文本类格式：本地 anydoc 解析。
3. 兜底：Docling 解析。
4. 纯文本（txt、md、markdown、rst、json、xml）不走转换链，直接读入原文（桌面端也是直接读文本，不经过转换引擎），不依赖任何组件。
5. 音视频：先走 Docling media，失败再用 ffmpeg 抽音 + ASR；视频还需要配置视觉模型才能生成时间线总结，否则任务失败并在错误中说明原因。

长 PDF 会先按上传上限分段并并发解析，失败的分段再降级到本地引擎，任务详情里显示「第 N/M 段」的分段进度。分段路径以 MinerU 为主，因此「PDF 首选引擎」选 anydoc 或 Docling 时会跳过分段，直接整文件用所选引擎开始；选 MinerU 或自动时仍走分段路径。

任务按文件内容 MD5 去重：同一文件重复提交直接返回已有任务，不重复解析。提交时可带 `client_id`，用于在任务列表与日志中区分调用方。上传的文件在磁盘上按 MD5 分层存放，原始文件名另存在任务记录里，列表、详情与下载都显示原名。

## Docker 部署

一键部署（支持 x86_64 与 ARM64，镜像构建时按宿主机架构自动选择）：

```sh
cp .env.example .env   # 可选：填 SAG_MINERU_API_KEYS，多个 key 用逗号分隔；HF_ENDPOINT 默认是国内源
docker compose -f docker-compose.docling-base.yml build
docker compose up -d --build
```

启动后打开 `http://127.0.0.1:8005/ui/`。Docker 默认把宿主机 8005 映射到容器内 3001；可通过 `.env` 中的 `PORT` 修改宿主机端口。数据存在具名卷 `sag-parse-data` 里；想用本地目录挂载时，把 `docker-compose.yml` 里的 `volumes` 改成 `./data:/data`。

Docling 文档组件与音视频组件放在单独版本化的基础镜像 `sag-parse-server-base:a801f28` 中。第一次部署时先构建基础镜像；Rust crates 默认使用 `rsproxy.cn`，uv 和 Python 依赖使用清华 PyPI 镜像，Python 运行时使用 npmmirror，PyTorch CPU wheel 使用上海交大镜像，HuggingFace 模型使用 `https://hf-mirror.net`。uv 从 PyPI 镜像预装，避免构建时依赖 GitHub Release。可在 `.env` 中覆盖这些地址。基础镜像构建成功后，普通源码更新只构建应用镜像，不会重新安装或下载 Docling 组件。容器首次启动时，入口脚本先将组件从镜像复制进数据卷（本地复制，不联网），复制完成后才启动 API；健康检查为首次复制预留 30 分钟。

不填 MinerU key 也能启动（MinerU 未配置时走本地降级），key 也可在 Web 设置页里粘贴。环境变量里的 key 只驻留内存，不写入磁盘。

基础镜像约 6GB，首次构建约 15–40 分钟。后续升级 Docling 安装流程或依赖时，更换 `.env` 中的 `SAG_RUNTIME_BASE_IMAGE` 标签，再构建基础镜像并重建应用镜像。amd64 宿主机上构建 arm64 基础镜像会走 QEMU 模拟，安装步骤明显更慢；arm64 建议用原生 ARM 构建机或 buildx 远程 ARM 节点。

多架构发布（一次构建两个架构并推送）：

```sh
docker buildx build --platform linux/amd64,linux/arm64 --target runtime-base --build-arg HF_ENDPOINT=https://hf-mirror.net -t <基础镜像>:<标签> --push .
docker buildx build --platform linux/amd64,linux/arm64 --build-arg SAG_RUNTIME_BASE_IMAGE=<基础镜像>:<标签> -t <应用镜像>:<标签> --push .
```

注意：若宿主机设置了 `HTTP(S)_PROXY`，MinerU 请求被代理时可能超时；`docker-compose.yml` 已把 MinerU 相关域名写进 `NO_PROXY` 做直连。

## 启动

```sh
sag parse-server
sag parse-server --port 3002 --data-dir /path/to/data
```

默认监听 `0.0.0.0:3001`，数据目录默认为 SAG 数据目录。服务启动后在数据目录下生成 `parse-uploads/`、`parse-outputs/`（内含 `docs/` 与 `temp/`）、`parse.db` 与 `sag.sqlite`。

服务无鉴权，仅供内网使用，不要直接暴露到公网。

## Docling 组件

本地解析靠两个 Docling 组件，Docker 镜像在构建期已全部装好；不用 Docker 时可用 CLI 安装：

```sh
sag docling install                  # 默认同时装文档与音视频两个组件
sag docling install --profile documents   # 只装文档组件
sag docling install --profile media       # 只装音视频组件
sag docling install --data-dir /path/to/data  # 指定数据目录，默认 SAG 数据目录
```

- **文档组件**：Python 3.12 + docling + 布局、TableFormer、RapidOCR 模型；html、msg、zip 等格式与 PDF/Office 的本地降级都靠它。
- **音视频组件**：openai-whisper + whisper-tiny 模型 + 内置 ffmpeg；音视频走 Docling media 时用它。

组件装在数据目录下（`docling/` 与 `docling/media/`），一次安装后一直可用。基础镜像里预装的组件在 `/opt/sag/docling-documents` 与 `/opt/sag/docling-media`；Docker 入口脚本在 API 启动前调用 `sag docling install`，将组件复制进数据目录。已有组件时不会重复复制。自己预构建组件目录也可以用 `SAG_DOCLING_COMPONENT_DIR` / `SAG_DOCLING_MEDIA_COMPONENT_DIR` 指向（目录里须有 `manifest.json`、Python、site-packages 与模型）。

组件安装与启动遵循同一数据目录里的「网络代理」设置（桌面端或 CLI 配置，解析服务的 Web UI 不单独配置）：`sag docling install` 与解析服务自动拉起组件时都使用这份代理，未配置时直连。

## Web UI

Docker 默认部署时，浏览器打开 `http://127.0.0.1:8005/` 或 `http://127.0.0.1:8005/ui/`，即可使用 Web UI：

- **任务总览**：拖拽或选择文件上传（可多选），填写 `client_id`；查看任务状态、进度、当前引擎与耗时；取消或重启任务。上传表单没有 prompt（SAG 桌面原来也没有）；prompt 只在任务详情「重试（新 prompt）」与 `/convert` 的 `task_id` 重跑模式里用。
- **任务详情**：引擎尝试链（每步耗时与错误原文）、PDF 分段进度、Markdown 渲染预览与源码切换、复制与下载。
- **设置**：按文件类型选首选引擎（文档解析）、MinerU 多 Key、音视频、队列与日志；每个引擎点「配置」打开单独的设置表，保存后即时生效。
- **日志**：按级别与任务筛选的结构化日志。

## 支持的格式

| 类型 | 扩展名 | 引擎 |
| --- | --- | --- |
| PDF | pdf | 按类型首选引擎（默认 MinerU → anydoc → Docling） |
| 图片 | png、jpg 等 | 按类型首选引擎（默认 MinerU → Docling） |
| Office | doc、docx、ppt、pptx、xls、xlsx、rtf、odt、html、csv、epub 等 | 按类型首选引擎（默认 anydoc → Docling） |
| 纯文本 | txt、md、markdown、rst、json、xml | 直读原文（text），不走转换链 |
| 音频 | wav、mp3、flac、m4a、ogg、opus、webm | 首选 Docling media 或 ASR 直转；Docling media 失败后走 ffmpeg + ASR |
| 视频 | mp4、mov、avi、mkv | 首选 Docling media 或时间线总结（ASR + 视觉模型） |

不支持的格式会在提交时按文件返回错误，不影响其他文件。

## API

Docker 默认部署的基础地址为 `http://127.0.0.1:8005`（容器内仍监听 3001）；直接运行 `sag parse-server` 时默认基础地址为 `http://127.0.0.1:3001`。请求与响应均为 JSON（上传接口为 `multipart/form-data`）。所有提交接口同时接受表单字段 `client_id` 与请求头 `X-Client-Id`，表单优先，`client_id` 会存进任务记录与日志。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/health` | 服务状态与各状态任务计数 |
| POST | `/convert` | 上传 `files[]` 提交解析，或用 `task_id` + `prompt` 重跑；返回每文件的 `task_id` 与状态 |
| POST | `/tasks` | 表单提交已上传文件：`input_file`（uploads 下相对路径，必填）、`filename`（原始文件名，可选，用于列表展示）、`output_file`、`task_id`、`client_id` |
| GET | `/tasks/{id}` | 任务记录，含尝试链、进度与耗时 |
| GET | `/api/tasks?status=&client_id=&search=&page=&page_size=` | 任务列表，按创建时间倒序；支持按状态、`client_id` 筛选与按原始文件名/上传路径/`task_id` 搜索，`page_size` 默认 20、上限 100 |
| GET | `/tasks/{id}/result` | 完成后返回内联 `markdown`；进行中返回状态；失败返回 500 与错误原文 |
| POST | `/tasks/{id}/restart` | 仅 failed/completed 可重启 |
| POST | `/tasks/{id}/cancel` | pending 直接取消；processing 置取消标志，任务结束为失败 |
| GET | `/uploads/...` | 只读，供外部 ASR/视觉后端按 URL 取文件 |
| GET/PUT | `/api/settings` | mineru、engines、docling、files、queue、asr、vision、logs 八组设置；PUT 接受部分合并，保存后新任务即时生效 |
| GET | `/api/settings/mineru-keys` | MinerU Key 列表，只返回掩码与统计 |
| POST | `/api/settings/mineru-keys` | 新增 Key 到下一空闲槽位 |
| DELETE | `/api/settings/mineru-keys/{index}` | 删除指定槽位的 Key |
| GET | `/api/logs?level=&task_id=&limit=` | 结构化日志，默认 100 条，上限 1000 条 |

提交示例：

```sh
curl -F "files=@report.pdf" -F "client_id=my-app" http://127.0.0.1:8005/convert
curl http://127.0.0.1:8005/tasks/<task_id>/result
```

## MinerU 多 Key 配置

解析服务只支持 MinerU 官方（mineru.net），302.AI 已移除：设置页不再提供 302 选项，`PUT /api/settings` 与新增 Key 接口收到 `302` 会直接报 400；桌面端若配了 302，解析服务仍走官方（需在解析服务里另配官方 Key）。Key 按槽位保存在凭据文件中，设置接口与日志只返回掩码（如 `****后 4 位`），永不返回明文。

- 在 Web UI 设置页新增 Key，或调用 `POST /api/settings/mineru-keys`。
- 也可以用环境变量 `SAG_MINERU_API_KEYS`（逗号分隔）注入 Key，只驻留内存，不写入磁盘。
- 多个 Key 按轮询分配；某个 Key 遇到 429 或额度类错误后进入冷却（默认 60 秒，可在设置中调整），冷却期间自动使用其他 Key。
- 每个 Key 的成功、失败与页数单独统计，可在设置页或 `GET /api/settings/mineru-keys` 查看。
- MinerU 失败不阻断任务：失败后自动降级到本地解析；429 切换体现在下一个任务选用另一 Key。

## 设置说明

- **每种类型选首选引擎**：PDF、Office 文档、图片各选一个首选引擎（自动 / MinerU / anydoc / Docling，图片没有 anydoc）；选中的引擎先试，失败后其余引擎仍按默认顺序降级。PDF 选 anydoc 或 Docling 这类本地引擎时会跳过 MinerU 分段路径，保证首选引擎先跑；选 MinerU 或自动仍按分段路径并发解析。音频可选 Docling media 或 ASR 直转，视频可选 Docling media 或时间线总结（ASR + 视觉模型）。
- **每个引擎单独配置**：点「配置」打开该引擎的设置表——MinerU（开关、模型、解析方式、OCR/表格/公式、超时与并发）、anydoc（Office 仅提取文字、大小上限）、Docling（超时、线程、OCR/表格）、ASR（引擎、服务地址、模型、超时与切片）、视觉模型（服务地址、模型、Key、系统提示词）。
- **队列并发**：默认 4，可在 1–16 之间调整，改动对新启动的任务即时生效。
- **MinerU 并发**：云端并发默认 2，可在 1–16 之间调整。
- **MinerU 开关**：设置里的 MinerU 开关分三态——未显式设置时自动启用（Key 池或桌面凭据里有 Key 即启用）；显式打开/关闭后按选择执行，`false` 时即使有 Key 也不调 MinerU。
- **ASR**：支持 FunASR、OpenAI 兼容接口与 VibeVoice 三种引擎，长录音按静音或等分切片，单段上限 25 MiB。
- **视觉模型**：OpenAI 兼容的 `/v1/chat/completions` 接口，用于视频时间线总结；未配置时视频任务失败，纯音频任务不受影响。
- **日志保留**：默认 30 天，保存设置时清理过期日志。

## 已知限制

- 队列并发改动即时生效；输出目录改动只影响之后创建的任务。
- html、msg、zip 等格式 anydoc 不处理，只能走 Docling；Docker 镜像自带 Docling 组件，不用 Docker 时未安装会失败并在错误中说明原因，可用 `sag docling install` 安装。
- MinerU 的 429 切换发生在任务粒度，同一任务内不重试另一 Key。
- 视频任务在视觉模型未配置时失败（ASR 阶段已完成，错误原文会说明原因）。
- 任务列表的 `search` 匹配原始文件名、上传路径（含 MD5 分层目录）与 `task_id`；升级前创建的任务记录没有原始文件名，只能按上传路径与 `task_id` 搜索。
